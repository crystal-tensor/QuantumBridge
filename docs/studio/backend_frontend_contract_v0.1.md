# QuantumBridge Studio Backend/Frontend Contract v0.1

Stage 10E defines the local contract between the Python Studio backend and the
static frontend prototype.

## Canonical Source

The backend workflow registry is canonical. Frontend workflow data must be
generated from `quantumbridge.studio.frontend_contract`, not hand-maintained.

Required bundle sections:

- catalog
- workflows
- workflow_details
- results
- benchmark
- exports
- schema

Every section includes schema version, generated timestamp, source,
QuantumBridge version, warnings, provenance, and clean-room notice.

## Coverage Rules

- `sampleWorkflows.json` covers every backend registered workflow.
- `sampleWorkflowDetails.json` covers every backend registered workflow.
- Every workflow detail includes input schema, default inputs, output schema,
  result schema, warnings, provenance, limitations, and clean-room notice.
- `sampleResults.json` includes at least 10 succeeded representative workflow
  results.
- `sampleBenchmarkReport.json` is generated by the local benchmark service.
- `sampleExports.json` includes JSON, Markdown, Python snippet, and notebook
  stub samples.

## Boundaries

The contract is local-only. It does not start a production server, open a public
port, access cloud services, read tokens, execute hardware, copy upstream UI or
prose, or claim official endorsement.
